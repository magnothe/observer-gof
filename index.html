Fase 1 · o problema

Um mundo sem Observer

A Loja vai receber o iPhone 17: Ana e Bruno querem; Carlos e Duda não. Sem um mecanismo de inscrição só existem dois caminhos, e os dois são ruins. Experimente.

0 viagens perdidas — o cliente fica consultando (polling) precisa de 5 para liberar a Fase 2
0 mensagens de spam — a loja avisa quem não tem interesse precisa de 1 envio para liberar a Fase 2

É esse o conflito.

Se o cliente fica consultando, ele desperdiça viagens. Se a loja avisa todo mundo, ela gera spam. O Observer resolve invertendo a responsabilidade: quem tem interesse se inscreve, e a loja notifica só a lista de inscritos.

Desafio da fase

Faça só a Ana e o Bruno receberem a promoção, sem que o Carlos receba. Depois clique em lancarPromocao(...) para confirmar.

Desafio concluído.

A loja não decidiu nada: ela só chamou notify("promocao", ...). Quem definiu o destino foi a lista de assinantes. Zero viagem perdida, zero spam.

          definição formal
          

            O Observer é um padrão de projeto comportamental que permite definir um mecanismo de inscrição
            para notificar múltiplos objetos sobre quaisquer eventos que aconteçam com o objeto que eles estão observando.
          

          

            Vocabulário: a publicadora mantém a lista de assinantes; quem quiser receber avisos chama inscrever
            e pode cancelar inscrição a qualquer momento; quando o evento acontece, a publicadora notifica a lista
            chamando update em cada assinante.
